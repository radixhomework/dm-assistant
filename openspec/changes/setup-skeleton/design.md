# Design — setup-skeleton

## Context

Greenfield: the repository holds planning documents only (`PRODUCT.md`, `ARCHITECTURE.md`, `templates/`, `PRE-SPEC.md`, `ROADMAP.md`). `ARCHITECTURE.md` §2 has already fixed the stack (NestJS modulith, React + Vite + TS, Drizzle, Zod, Postgres) and §1 the single-door shape; this change wires them into a running monorepo. See proposal.md for motivation and `specs/project-skeleton/spec.md` for the behavior contract.

## Goals / Non-Goals

**Goals:**

- A workspace where `pnpm install && docker compose up` produces a reachable shell, and `pnpm lint / typecheck / test / build` pass from a clean checkout.
- The module boundary of the future modulith (module-per-domain folder convention) visible from day one, so P1+ work slots in without re-plumbing.
- Config loading that fails fast with named errors, using the shared Zod schema package.

**Non-Goals:**

- No domain features: no auth, no accounts, no records CRUD, no real MCP tools, no MinIO, no reverse proxy, no PWA offline shell (`vite-plugin-pwa` lands in P6), no admin panel.
- No production deployment concerns (image build comes with the GitOps deploy work in P6).

## Decisions

1. **npm workspaces, Node 26 LTS** — `app`, `app-web` and `packages/*` layout managed by npm workspaces (local configuration decision: npm inside WSL, replacing the initial pnpm assumption; Docker 29 + Compose v5 also live in WSL). Node 26.13.0 LTS activated through nvm (`.nvmrc`); enforced via `engines` so CI matches. All frameworks are taken at their latest stable major at implementation time and pinned by the lockfile — **except TypeScript, pinned to 5.9** because typescript-eslint 8 does not support TS 7 yet (peer range `< 6.1.0`); revisit when it does.
2. **NestJS 11 on the default Express platform** — Fastify is already a rejected alternative in `ARCHITECTURE.md` §2; Express keeps `serve-static` SPA fallbacks trivial. Modules created as empty skeletons matching `ARCHITECTURE.md` §4 (`entities`, `calendar`, `relationships`, `mentions`, `proposals`, `annotations`, `external-refs`, `assets`, `search`, `audit`, `auth`, `mcp`) — only `config` and `mcp` contain behavior in P0.
3. **Single-door validation inside the dev stack** — the compose `app` service runs a **production-style build** (frontend built, then served by Nest via `@nestjs/serve-static` with SPA fallback, `/api` and `/mcp` excluded from the fallback). This validates the real deployment path (`docker compose up` = shell + API from one process). Hot-reload development stays a local, non-compose workflow (`pnpm dev` with Vite dev server proxying `/api`).
4. **Config as a shared Zod schema** — `packages/schemas` exports `envSchema` (parsed once at bootstrap via the Nest config module's `validate`); the same package will later host record schemas. Failure aborts startup listing the offending variable names.
5. **Drizzle + `postgres-js` driver, `drizzle-kit` for migrations** — one `migrations` folder with SQL generated by the kit; the first migration creates `settings(key UNIQUE, value, updated_at)`. `DATABASE_URL` defaults to the compose service (`postgres://dm:dm@postgres:5432/dm_assistant`). Migrations run via an explicit `pnpm --filter app db:migrate` command (wired into the app bootstrap as a documented step, not auto-run on boot in P0).
6. **i18n: `react-i18next` with JSON catalogs + a parity unit test** — `apps…/src/i18n/{fr,en}/*.json` namespaces flattened to one key set; a Vitest test asserts both catalogs expose identical key sets (this is the CI catalog-parity gate of the spec). Shell labels are seeded in both languages; language resolution reads `UI_LOCALE` (injected into the shell via the served config endpoint or build-time env — build-time for P0).
7. **MCP mount without tools** — the official `@modelcontextprotocol/sdk` Streamable HTTP transport is mounted at `/mcp` and answers correctly (initialize handshake, empty tool list). Unauthenticated in P0: acceptable because the tool list is empty and nothing is exposed; auth arrives with P1. Recorded as a risk below.
8. **CI: single GitHub Actions job with a Sonar quality pass** — `npm ci` → `build` → `lint` → `typecheck` → `test` (coverage enabled) → **SonarQube scan** (`sonarsource/sonarqube-scan-action@v8`) → **quality-gate wait** (`sonarsource/sonarqube-quality-gate-action@v1`). Project key follows the org convention (`radixhomework_dm-assistant`); coverage comes from vitest (lcov) in the three packages, reported through `sonar.javascript.lcov.reportPaths`. The scan uses the `GH_SONAR_TOKEN` organization secret. **The org quality gate requires 80% coverage on new code** — every non-wiring file carries unit tests, and bootstrap/wiring files are excluded from coverage (`sonar.coverage.exclusions`: `main.ts`, `migrate.ts`, Nest `*.module.ts`, `main.tsx`). Sonar classification pitfalls handled: `sonar.test.inclusions` must list `**/*.test.ts`, `**/*.test.tsx` **and** `**/*.spec.ts` — otherwise test files count as uncovered production code.
9. **Visual theme: RadixHomeWork inheritance** — Tailwind v4 `@theme` tokens carry the palette and fonts of the RadixHomeWork theme (recorded in `ARCHITECTURE.md` §3): Cormorant Garamond (display) + Source Sans 3 (body) via Google Fonts, background `#FCFCFA`, surface `#D8D0BD`, text `#1E211C`, muted `#76604E`, primary `#4D5947`, accent `#9A7656`, border `rgba(30,33,28,0.2)`; flat style (no shadows, `translateY` hovers, `0.2s ease`). UI work in this and later phases runs through the impeccable skills present in the repository (`.agents/skills/impeccable/`).

## Risks / Trade-offs

- [Unauthenticated `/mcp` mount during P0–P1] → transport answers with an empty tool list and writes nothing; replaced by Bearer-token auth in P1 before any tool exists.
- [Compose runs a production build, so no hot reload inside Docker] → accepted: compose validates the single door; local `pnpm dev` provides watch mode. Documented in the README.
- [Frontend dependency churn (latest majors: React, Vite, Tailwind)] → exact versions pinned in the lockfile; CI build catches breakage on every push.
- [`serve-static` SPA fallback shadowing `/api` or `/mcp`] → fallback configured with explicit exclusions; health-check scenario in the spec guards it.
- [Windows development (LF/CRLF)] → `.gitattributes` with `* text=auto eol=lf` added in this change to stop the CRLF churn already visible in commits.
